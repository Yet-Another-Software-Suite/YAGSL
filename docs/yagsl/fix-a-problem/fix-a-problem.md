# Find your problem

Find the row that matches what your robot is doing, and start with the page it points to. Several problems can be present at once, so if the first fix doesn't settle it, work down the table.

{% hint style="info" %}
Prefer to work step by step? [Troubleshooting](troubleshooting.md) checks a swerve drive in stages, from the basics up. Most problems come from a step skipped during setup. If you haven't been through [Check and calibrate your hardware](../get-started/04-verify-and-calibrate-hardware.md), do that first: it catches inversions, bad offsets and CAN ID mistakes in a few minutes. For checklists, see [Common build issues](common-build-issues.md) and [Common configuration issues](common-configuration-issues.md).
{% endhint %}

## The robot program won't start, or a device does nothing

| What you see                                                                    | Start here                                                                                                                                                                                                  |
| ------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| The robot program crashes at startup with a missing class error                 | A vendor library is missing. See [Vendordeps and offline install](../reference/vendordep-installation.md#optional-vendor-libraries).                                                                        |
| A SPARK isn't found, or `canbus` is rejected with an `IllegalArgumentException` | [Fix common SparkMAX/SparkFlex problems](fix-sparkmax-common-problems.md)                                                                                                                                   |
| A SparkMAX doesn't move, with no error                                          | Its CAN ID is shared with another device, such as the REV Power Distribution Hub. Every CAN ID must be unique on its bus. See [Put devices on a different CAN bus](../tune-and-extend/choose-a-can-bus.md). |
| Status frame errors from a SparkMAX                                             | A loose or broken sensor cable. See [Fix common SparkMAX/SparkFlex problems](fix-sparkmax-common-problems.md).                                                                                              |

## On blocks: the modules don't point or spin correctly

| What you see                                                                                      | Start here                                                                                                                                                                                                                                                                           |
| ------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| One or more modules spin "out of control"                                                         | [Troubleshooting](troubleshooting.md)                                                                                                                                                                                                                                                |
| One module acts up, or doesn't start in the right position every time                             | A disconnected absolute encoder, an encoder too far from its magnet, a loose magnet, wrong gearing, a dying motor, or a module built incorrectly. See the [One module doesn't start in the right position](troubleshooting.md#one-module-doesnt-start-in-the-right-position) checks. |
| A module points the wrong way, or its readings go the wrong way when turned by hand               | [Determine inversion](determine-inversion.md), steps 1 and 2                                                                                                                                                                                                                         |
| In the spin test, one wheel pushes against the others                                             | That module's drive motor is inverted. See [Determine inversion](determine-inversion.md), step 3.                                                                                                                                                                                    |
| In the spin test, the robot spins clockwise instead of counterclockwise                           | A diagonal module swap, inverted drive motors, or offsets captured with the bevel gears facing right. See [Determine inversion](determine-inversion.md), step 3.                                                                                                                     |
| Driving straight, the modules don't all point forward                                             | A wrong CAN ID, device type, module order, location or offset, or untuned azimuth gains. See the [Wheels not pointing straight](troubleshooting.md#wheels-not-pointing-straight) checks.                                                                                             |
| Gears grind on the ground but not on blocks, with every wheel pointing and spinning the right way | The gains need tuning, not inverting. See [Tune PIDF gains](../tune-and-extend/tune-pidf-gains.md).                                                                                                                                                                                  |

## On the ground: field-relative driving is wrong

| What you see                                                                                                                                            | Start here                                                                                                                                                                                                                                                                                   |
| ------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Driving is wrong at every heading, including the starting one                                                                                           | Check `gyroInvert`. See [Determine inversion](determine-inversion.md), step 4.                                                                                                                                                                                                               |
| In field-relative driving, driving is right at the starting heading, but the directions change as the robot turns, or forward isn't forward in odometry | [The 8 steps](the-8-steps.md)                                                                                                                                                                                                                                                                |
| The robot drives forward, but odometry shows it driving backward                                                                                        | Add `180` to every `absoluteEncoderOffset`. See the "Odometry mismatch" note in [Determine inversion](determine-inversion.md), step 4.                                                                                                                                                       |
| "Forward" is the wrong side of the robot                                                                                                                | Front is whatever the gyro reports as `0`. See [Verify your module locations](verify-module-locations.md).                                                                                                                                                                                   |
| The field-relative heading is off after a while, or the robot powered on facing the wrong way                                                           | Zero the gyro with the button combo from [Write the swerve code](../get-started/write-the-swerve-code.md). If the gyro drifts, recalibrate it too: gyros are sensitive to pressure, and sometimes humidity, and an older one such as a Pigeon 1 or NavX 1 drifts the longer it's powered on. |

## It drives, but not well

| What you see                                                                                                   | Start here                                                                                                                                                                                                                                                      |
| -------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| The robot slides off its line while it drives                                                                  | The [Robot is drifting](troubleshooting.md#robot-is-drifting) checks (slides off its line), then [Fix swerve drive drift](swerve-drift-causes.md)                                                                                                               |
| The robot's heading turns on its own while it drives                                                           | The [Robot is drifting](troubleshooting.md#robot-is-drifting) checks (heading turns), then [Fix swerve drive drift](swerve-drift-causes.md)                                                                                                                     |
| The modules are slow to reach their angle, overshoot, or shake                                                 | [Tune PIDF gains](../tune-and-extend/tune-pidf-gains.md)                                                                                                                                                                                                        |
| Driving hard, such as in a match or practice, the modules fall behind their angles, but they're fine on blocks | The angle motor's current limit is too low. Raise `statorCurrentLimit.angle` in [physicalproperties.json](../reference/json-schema/physicalproperties-json.md). See the [Wheels not pointing straight](troubleshooting.md#wheels-not-pointing-straight) checks. |
| The robot drives slower than it should                                                                         | A module running backwards, scaling in the drive code, the maximum speed, the gains, the gear ratio or wheel diameter, or a full SystemCore. See the [Robot drives slower than it should](troubleshooting.md#robot-drives-slower-than-it-should) checks.        |
| Autonomous ends short or long by about the same amount every time                                              | The gear ratio or wheel diameter is off, or the wheel tread has worn down. See the [Autonomous is consistently off](troubleshooting.md#autonomous-is-consistently-off) checks.                                                                                  |
| PathPlanner paths overshoot or end in the wrong place                                                          | [Fix swerve drive drift](swerve-drift-causes.md), then [Set up PathPlanner](../tune-and-extend/setup-pathplanner.md)                                                                                                                                            |

## Still stuck?

Your robot records a DataLog every time it runs, since YAGSL turns it on by default. Open the one from when the problem happened with [View your DataLog in AdvantageScope](../tune-and-extend/view-your-datalog-in-advantagescope.md). Then ask on the [YAGSL Discord](https://discord.gg/yass) with your `swerve/` config directory and the log attached.
